버전마다 바뀐 점입니다. 새 버전 설치 파일을 그대로 실행하면 덮어 설치되고, 검색 폴더 · 설정은 남습니다.

0.1.7 2026-11-19 최신

기본 답변 모델의 정확도를 높이고, 문서에서 읽는 글을 넓힌 판입니다.

바뀐 점

  • 답변이 더 정확해짐(기본 모델): 기본 답변 모델 Qwen3-1.7B 에게 근거를 줄 때 가장 관련 높은 근거를 질문 바로 앞에 둡니다. 작은 모델은 질문 가까이 있는 글을 더 잘 쓰기 때문입니다. 시험 문서 질문 100개에서 정답이 46개 → 54개로 늘었습니다. 근거 번호는 그대로라 답 끝의 [1] 은 여전히 가장 관련 높은 근거입니다. 다른 답변 모델(Mi:dm · Qwen3.5-4B 등)은 시험해 보니 좋아지지 않아 예전 순서 그대로 둡니다.
  • 문서의 본문 밖 글도 읽기: PDF 글상자(숨긴 글상자 포함) · PDF 서식 칸에 적힌 값 · Word 메모 · PowerPoint · Word 의 SmartArt 글을 함께 읽어 검색에 넣습니다. 예전에는 이런 글이 빠져 찾을 수 없었습니다. 엑셀 셀 메모를 일부 파일에서 놓치던 문제도 고쳤습니다 (struct_docparse 0.2.0).
  • 파일 속성에 버전 표시: 탐색기 → 속성 → 자세히에서 MoAISearch.exe · simplerag-rs.exe 의 파일 버전 · 제품 이름 · 저작권이 보입니다.
인덱스를 다시 만들 필요는 없습니다. 0.1.6 위에 그대로 덮어 설치하면 됩니다.
이미 읽어 둔 문서는 그대로 남고, 본문 밖 글은 새로 더하거나 바뀐 문서부터 읽습니다. 답변 정확도 개선은 설치 직후 바로 적용됩니다.

릴리스 v0.1.7 · MoAISearch_Setup_0.1.7.exe

0.1.6 2026-11-17

스캔 문서 읽기(OCR)를 더 정확하고 빠르게 고친 판입니다. 0.1.5 는 내부 시험판이라 공개하지 않았습니다.

바뀐 점

  • 옆으로 누운 스캔 쪽 바로 세우기: 90° 돌아간 채 스캔된 쪽을 스스로 알아보고 바로 세워 읽습니다. 예전에는 반대 방향으로 누운 쪽에서 글자를 16~25%만 읽었고, 읽은 쪽도 줄 순서가 거꾸로 섞였습니다. 누운 채 스캔된 제안서 137쪽으로 시험해 모든 쪽을 바로 세웠습니다. 거꾸로(180°) 뒤집힌 쪽은 아직 그대로입니다.
  • 스캔 문서 구조 나누기: 스캔 문서에서 읽은 글을 제목 · 문단 · 머리말 · 꼬리말 · 목록으로 나눠 넣습니다. 쪽마다 반복되는 회사 로고 · 쪽 번호가 본문에 섞이지 않고, 위 제안서는 쪽마다 문단 두어 개로 뭉치던 것이 제목 · 본문으로 나뉘었습니다.
  • 작은 쪽 더 선명하게: A5 · A6 처럼 A4 보다 작은 PDF 쪽은 최대 1.4배 해상도로 읽어 작은 글자를 덜 놓칩니다(시험 문서 글자 +14%). 대신 그런 쪽은 읽는 시간이 약 30% 늘어납니다.
  • OCR 이 빨라짐: 같은 쪽을 읽는 시간이 약 1/3 줄었습니다(실제 스캔 문서 335쪽 연속: 쪽당 4.0초 → 2.7초). A4 보다 큰 쪽(포스터 · 도면 등)은 A4 크기로 줄여 읽어 메모리를 덜 씁니다.
  • 고친 문제: PDF 보기 프로그램에서 "페이지 회전"으로 돌려 저장한 스캔 쪽에서 머리말 · 꼬리말을 놓치던 문제를 고쳤습니다.
  • 문서 읽기 부품 분리: 문서를 읽고 OCR 하는 부분을 따로 떼어 냈습니다(struct_docparse 0.1.1). 일반 문서를 읽은 결과는 예전과 글자 하나까지 같습니다.
인덱스를 다시 만들 필요는 없습니다. 0.1.4 위에 그대로 덮어 설치하면 됩니다.
이미 읽어 둔 스캔 문서는 그대로 남고, 새로 읽는 스캔 문서부터 바로 세우기 · 작은 쪽 선명하게가 적용됩니다. 구조 나누기는 그 문서가 바뀌어 다시 인덱싱될 때 적용됩니다.

릴리스 v0.1.6 · MoAISearch_Setup_0.1.6.exe

0.1.4 2026-11-16

스캔 문서 글자 읽기(OCR)와 답변 모델 고르기(설정 > 모델)를 더하고, 메모리를 크게 줄인 판입니다.

새 기능

  • 스캔 문서 읽기(OCR): 글자층이 없는 PDF 쪽의 글자를 읽어 검색에 넣습니다. 그림 파일(.png · .jpg · .tif)도 읽습니다. 쪽당 2~3초라 다른 인덱싱이 끝난 뒤 질문이 없을 때 차례로 읽습니다. 설정 > 인덱싱의 스캔 문서에서 대기 · 지금 읽는 문서 · 끝난 문서를 보고 [잠시 멈춤]할 수 있고, 탐색기 창 맨 아래 줄에 "스캔 문서 읽는 중 N / M쪽"이 보입니다. 한 문서는 앞 100쪽까지 읽습니다.
  • 답변 모델 고르기(설정 > 모델): 답변 모델을 목록에서 골라 받고 바꿉니다. 이 PC의 메모리 · 그래픽 사양을 보고 알맞은 모델을 추천하고, 모델마다 예상 첫 글자 시간 · 사내 문서 시험 결과 · 라이선스를 보여 줍니다. 기본 모델(3B 이하, 빠른 답)과 정밀 모델(3B 이상, 더 정확하지만 느림)로 나뉘고, 받는 중 · 설치 중에는 진행 막대와 [취소] · [중지]가 있습니다. 받기가 막힌 곳에서는 [배포 페이지 열기]로 설치 파일을 직접 받아 실행할 수 있습니다.
  • Kanana-2 1.3B (시험판): 카카오의 2세대 한국어 소형 모델입니다. 일반 llama.cpp 가 읽지 못하는 구조라 고친 llama.cpp 판(약 60MB)이 함께 설치되고, 이 모델을 고를 때만 씁니다. 사내 문서 시험 전이라 추천에는 넣지 않았습니다. Powered by Kanana.
  • 지금 답변 모델 · 버전 표시: 탐색기 창 맨 아래 줄과 채팅 창 입력란 아래에 답하는 모델 이름이, 설정 창 로고 옆에 버전이 보입니다. CPU 로 답하고 있으면 빨간 CPU(느림)이 붙습니다. 모델 이름을 누르면 설정 > 모델이 열립니다.
  • 설정 > 인덱싱: 검색 폴더 · 인덱싱 확장자 · 스캔 문서를 기본 탭에서 따로 떼어 냈습니다. 인덱싱된 문서 · 쪽 · 청크 수와, 진행 중인 숫자(검색 정확도 높이는 중 · 폴더 인덱싱 · 스캔 문서)가 빨간 글씨로 보입니다.

바뀐 점

  • 메모리 절감: 5분 동안 질문이 없으면(스캔 문서를 읽는 중이면 3분) 답변 모델과 리랭커를 메모리에서 내려 약 2GB(공유 GPU 메모리 포함)를 돌려줍니다. 입력칸에 글자를 치기 시작하면 미리 다시 올리므로 대개 기다리지 않습니다. 검색 저장소도 약 1.6GB에서 0.64GB로 줄었고, OCR 은 쪽을 다 읽으면 쓴 메모리를 바로 돌려줍니다.
  • 검색이 빨라짐: 질문당 검색 계산이 약 3배 빨라졌습니다. 찾는 결과는 그대로입니다.
  • 답변 모델과 상관없이 같은 검색 결과: 어떤 답변 모델을 고르든 같은 질문이면 같은 근거를 찾습니다(리랭커를 PC 기준으로 켭니다).
  • 사람 이름으로 찾기: "장진영 대표"처럼 이름만 쓰면 문서 속성(작성자 · 수정자)에 그 사람이 있는 문서와 함께 본문에 그 이름이 나오는 문서도 찾습니다. "작성한 · 만든"을 붙이면 예전처럼 작성자로만 거릅니다.
  • 정밀 모드 → 설정 > 모델: 정밀 모드 켜고 끄기와 따로 받던 정밀 모델 설치 파일이 없어지고, 설정 > 모델에서 고릅니다. 0.1.3에서 정밀 모드를 켜 두었다면 같은 Qwen3-4B 모델로 옮겨 씁니다.
  • 화면: 시작할 때 띠 글이 "검색 준비 중"으로 바뀌었고, 탐색기 · 채팅 창이 항상 위에 있어도 설정 창이 가려지지 않습니다. 설정 > 로그는 경고 · 오류와 로그 폴더가 위로 올라왔습니다. [?] > 사용 안내에 비슷한 문서 찾기 · 답변 모델 · 스캔 문서 안내를 더했습니다.
  • 고친 문제: Qwen3.5 모델로 답하거나 AI 정리를 할 때 프로그램이 다시 시작되던 문제, 글을 도형으로 그린 PDF · 이름만 .bmp 인 그림이 실패 알림을 되풀이하던 문제, 같은 문서를 두고 "지금 인덱싱할까요?"를 계속 묻던 문제를 고쳤습니다.
인덱스를 다시 만들 필요는 없습니다. 0.1.3 위에 그대로 덮어 설치하면 됩니다. 0.1.2 이하에서 올리면 아래 0.1.3의 안내를 따르세요.
올린 뒤 처음 폴더를 대조할 때 그림 파일과 예전에 "글자 없는 PDF"로 실패한 문서가 새 문서로 잡힙니다. 50건이 넘으면 폴더 옆에 대기가 붙으니, 폴더를 오른쪽 클릭해 지금 인덱싱을 누르세요. 그림 파일을 읽지 않으려면 먼저 설정 > 인덱싱의 그림 파일도 읽기를 끕니다.

릴리스 v0.1.4 · MoAISearch_Setup_0.1.4.exe

0.1.3 2026-11-12

비슷한 문서 찾기와 인덱싱 실패 문서 보기를 더한 판입니다.

새 기능

  • 비슷한 문서 찾기: 결과 줄을 오른쪽 클릭해 이 문서와 비슷한 문서 찾기를 누르거나, 탐색기 입력란의 [+]를 누르거나, 입력란에 파일을 끌어 놓으면 내용이 비슷한 문서를 목록으로 보여 줍니다. 문서마다 비슷한 곳과 기준 문서의 맞닿은 부분(↔)이 함께 나오고, AI 답변창에는 넣은 문서의 요약이 나옵니다. 인덱스에 없는 바깥 문서도 넣을 수 있습니다(저장하지 않음).
  • 설정 > 로그: 인덱싱하지 못한 문서와 그 까닭을 보여 줍니다. 글자 없는 PDF(스캔본), 암호 걸린 문서, 형식을 알 수 없는 파일처럼 원인별로 묶고, 문서마다 [열기] · [폴더] · [다시 시도]가 있습니다. 최근 7일 로그의 경고 · 오류도 같은 내용끼리 묶어 횟수와 함께 보여 줍니다. 왼쪽 메뉴에 실패 수가 붙습니다(예: 로그 (12)).

바뀐 점

  • PDF 표 찾기: 테두리가 있는 표를 알아보고, 작은 표는 통째로 한 조각으로 넣어 표 안 내용을 묻는 질문에 더 잘 답합니다.
  • 파일 이름 바꾸기 바로 반영: 이름만 바꾼 문서를 다시 읽지 않고 옮긴 것으로 처리해 바로 새 이름으로 찾습니다.
  • 로그 파일 위치 · 이름: %LOCALAPPDATA%\MoAISearch\log\MoAISearch_날짜.log로 바뀌었습니다. 설정 > 로그의 [열기]로 폴더를 엽니다. 대화 기록은 예전 자리 그대로입니다.
  • 로그 폴더 보기를 설정 > 기본에서 설정 > 로그로 옮겼습니다.
0.1.2 이하에서 올린 경우: PDF 표 찾기로 문서를 나누는 규칙이 바뀌어, 예전 인덱스에서는 새 문서 · 고친 문서가 반영되지 않을 수 있습니다. 설정 > 로그의 경고에 청킹 설정이 인덱스와 다릅니다가 보이면 아래처럼 인덱스를 새로 만드세요(검색 폴더 · 설정 · 사전은 남습니다).
  1. 트레이의 MoAI 아이콘을 오른쪽 클릭해 [종료]를 누릅니다.
  2. 설치 폴더 %LOCALAPPDATA%\Programs\MoAISearch에서 rag_index 폴더와 index_state.json · bm25_index.bin · bm25_index.bin.delta 파일을 지웁니다.
  3. MoAI-S를 다시 켜면 검색 폴더를 처음부터 다시 읽습니다. 읽는 동안에도 읽은 문서부터 찾을 수 있습니다.
